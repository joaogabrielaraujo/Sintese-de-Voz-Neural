# Plano 13.7 — Validar release candidate Android via USB

## Tarefas

### 1. Preparar o ambiente de dispositivo

- Verificar `flutter doctor -v`, Android SDK, platform-tools e ADB.
- Ativar depuração USB no aparelho e aceitar a chave RSA.
- Confirmar o dispositivo com `adb devices` e `flutter devices`.
- Registrar modelo do aparelho, versão Android, arquitetura ABI e espaço livre.
- Confirmar que o modelo ONNX e o `espeak-ng-data` estão presentes no pacote/fluxo de instalação.

### 2. Executar smoke test conectado

- Rodar `flutter run -d <device-id>`.
- Importar o EPUB grande usado pelo usuário.
- Confirmar título, autor e capítulos.
- Abrir o Reader e trocar de capítulo.
- Iniciar a síntese e observar o log de inicialização do Sherpa-ONNX.
- Ouvir pelo menos dez transições consecutivas em velocidade 1× e 2×.
- Selecionar uma frase intermediária, cancelar e confirmar outra seleção.
- Voltar ao Home pela seta e importar um segundo arquivo.

### 3. Validar resiliência móvel

- Bloquear/desbloquear a tela durante uma leitura.
- Colocar o aplicativo em segundo plano e retorná-lo.
- Interromper a leitura durante síntese e iniciar novamente.
- Trocar de capítulo enquanto há itens na fila.
- Tentar arquivo inválido e cancelar o seletor.
- Observar RAM, temperatura, bateria, travamentos e mensagens nativas de áudio.

### 4. Gerar o release candidate

- Atualizar versão/build number sem apagar a possibilidade de rastrear o commit.
- Gerar APK de release candidate com `flutter build apk --release`.
- Instalar o APK via `adb install -r` em aparelho de teste.
- Repetir o smoke test essencial no APK, sem depender do hot reload.
- Guardar checksum do APK, commit, versão do modelo e data do teste em um relatório.

## Verificação automatizada

```text
flutter analyze
flutter test
flutter build apk --release
```

## Verificação manual obrigatória

O release não será considerado aprovado apenas por compilar. É necessário executar o fluxo em um aparelho físico via USB com um EPUB grande e registrar resultado por cenário.
