# Phase 09.1: Code Review Report

**Reviewed:** 2026-07-31T18:00:12Z  
**Depth:** deep  
**Files Reviewed:** 49  
**Status:** issues_found

## Summary

The default runtime path cannot produce usable neural speech. Its smallest root-cause chain is:

1. The bundled Faber Piper model requires `espeak-ng-data`, but the app packages only the model, tokens, lexicon, and README; the FFI config explicitly passes `dataDir: ''`.
2. Sherpa initialization/generation failures are swallowed and converted into estimated-duration arrays containing only zeros.
3. Auto-failover selects `VitsOnnxEngine`, which never creates an ONNX session and also returns only zeros while claiming initialization succeeded.
4. `CompositeTTSEngine` treats any non-empty sample array as success, so the pipeline wraps silence in a valid WAV, plays it, and reports favorable RTF metrics.
5. Tests assert only non-empty length/duration, allowing silent fabricated buffers to pass as “real inference.”

The CLI, Android system service, Web route, and UI engine selector are also non-functional. The Android release configuration additionally ships with debug signing, and the CLI exposes a Windows command-injection path if it becomes reachable.

`dart analyze` and Flutter tooling did not complete within the review environment's timeout. No finding below depends on compilation or test failure; each is supported by direct source and call-chain evidence.

## Critical Issues

### CR-01 [BLOCKER]: The Piper model's required `espeak-ng-data` is absent and `dataDir` is forced empty

**File:** `lib/core/engine/sherpa_onnx_engine.dart:61-70,91-99`; `pubspec.yaml:23-26`; `assets/models/README.md:5-8`  
**Issue:** Initialization extracts only the ONNX model, tokens, and lexicon, then creates `OfflineTtsVitsModelConfig` with `dataDir: ''`. The asset manifest has no `espeak-ng-data` bundle or extraction path. This exact Faber model is a Piper model whose official Sherpa configuration requires `espeak-ng-data`; the upstream Dart example sets it explicitly. The local ONNX metadata also identifies `model_type=vits`, `comment=piper`, and `has_espeak=1`. The generated finite lexicon cannot replace Piper's Portuguese phonemizer, and it is built from a fixed demo paragraph rather than the text being synthesized.

**Fix:** Bundle the complete official model directory, including `espeak-ng-data`; copy/extract it recursively into application storage; validate required files; and pass its absolute path as `dataDir`. Remove the custom lexicon unless the selected model explicitly requires one. Follow the [official Faber model configuration](https://k2-fsa.github.io/sherpa/onnx/tts/all/Portuguese/vits-piper-pt_BR-faber-medium.html).

```dart
final vitsConfig = sherpa.OfflineTtsVitsModelConfig(
  model: absModelPath,
  tokens: absTokensPath,
  lexicon: '',
  dataDir: absEspeakDataDir,
  noiseScale: config.noiseScale,
  noiseScaleW: 0.8,
  lengthScale: config.lengthScale,
);
```

### CR-02 [BLOCKER]: Sherpa failures are hidden and replaced with non-empty silence, defeating failover

**File:** `lib/core/engine/sherpa_onnx_engine.dart:115-119,175-216`; `lib/core/engine/composite_tts_engine.dart:105-122`  
**Issue:** `initialize()` catches every exception and returns normally. `synthesize()` catches generation errors or zero-sample output, then returns a positive-length `Float32List` initialized entirely to zero. `CompositeTTSEngine` checks only `samples.isNotEmpty`, so it accepts this silent buffer as successful neural inference and never activates another engine. This directly converts missing DLL/model/config failures into a playable silent WAV and a false success report.

**Fix:** Preserve failure semantics: throw a typed initialization/synthesis exception or return an explicit failure result. Never fabricate PCM on an inference failure. The composite must reject empty, non-finite, and effectively silent output before declaring success.

```dart
if (!_initialized || _tts == null) {
  throw StateError('Sherpa-ONNX is not initialized');
}
final audio = _tts!.generate(text: cleanText, sid: 0, speed: 1.0);
if (audio.samples.isEmpty) {
  throw StateError('Sherpa-ONNX generated no samples');
}
return AudioBuffer(
  samples: Float32List.fromList(audio.samples),
  sampleRate: audio.sampleRate,
);
```

### CR-03 [BLOCKER]: `VitsOnnxEngine` does not perform ONNX inference at all

**File:** `lib/core/engine/vits_onnx_engine.dart:20-24,35-64,102-128`  
**Issue:** The engine loads model bytes into an unused field, creates no ONNX Runtime session, never calls an inference API, ignores the generated token IDs, and fills every returned sample with `0.0`. It also sets `_initialized = true` when model/token loading fails. Because auto-failover prefers this engine before native TTS, the default path reliably terminates at a fake “successful” silent engine after Sherpa fails.

**Fix:** Remove this engine from production failover until it contains a real supported ONNX runtime implementation. Preferably use the already integrated Sherpa runtime for this model family. If retained, initialization must verify model and token compatibility, create a real session, run all VITS inputs/outputs, and fail closed when unavailable.

### CR-04 [BLOCKER]: `FlutterTtsEngine` violates the `AudioBuffer` contract and cannot be controlled by the app's player

**File:** `lib/core/engine/flutter_tts_engine.dart:28-40,43-70`; `lib/main.dart:204-215,431-449`  
**Issue:** Initialization marks the engine successful even when all platform-channel setup fails. Synthesis starts `flutter_tts.speak()` in an unawaited task, suppresses its errors, and immediately returns an estimated-duration buffer of zeros. The pipeline then separately loads and plays those zeros through `audioplayers`. Pause, seek, speed, stop, highlighting, and RTF operate on the silent WAV, not on native speech; rapid per-sentence calls may also replace or overlap native utterances. This is not an `ITTSEngine` implementation that returns synthesized audio.

**Fix:** Split native direct-speech from buffer-producing inference into different contracts. Either use a native API that synthesizes to a WAV/file and return its decoded PCM, or bypass `PipelineResult`/`AudioPlayerService` entirely and expose native speak/pause/stop/completion events. Propagate setup and speak errors, and do not claim buffer synthesis.

### CR-05 [BLOCKER]: The CLI engine is unreachable through the composite and invalid when invoked directly

**File:** `lib/core/engine/composite_tts_engine.dart:22-33,49-53,66-83`; `lib/core/engine/sherpa_onnx_cli_engine.dart:58-69,175-183`  
**Issue:** The composite never imports or constructs `SherpaOnnxCliEngine`; both `sherpaOnnx` and `sherpaOnnxCli` select the same FFI `_sherpaEngine`, and auto-failover never attempts CLI. Direct CLI execution uses `--tokens`, while Sherpa's offline TTS binary expects `--vits-tokens`, and it omits the required `--vits-data-dir`. Therefore the advertised isolated Windows fallback is both disconnected and misconfigured.

**Fix:** Construct a `SherpaOnnxCliEngine`, map `TTSEngineType.sherpaOnnxCli` to it, include it in the intended auto-failover order, extract the same `espeak-ng-data`, and invoke the official option names:

```dart
[
  '--vits-model=$_absModelPath',
  '--vits-tokens=$_absTokensPath',
  '--vits-data-dir=$_absEspeakDataDir',
  '--output-filename=$tempWavPath',
  cleanText,
]
```

### CR-06 [BLOCKER]: EPUB text can become Windows shell commands in the CLI path

**File:** `lib/core/engine/sherpa_onnx_cli_engine.dart:155-156,175-184`  
**Issue:** Arbitrary document text is passed as a process argument while `runInShell: Platform.isWindows` routes execution through `cmd.exe`. `removeDiacritics()` does not remove shell metacharacters such as `&`, `|`, `<`, or `>`. A malicious EPUB sentence can therefore append commands when the CLI route is used. Dart's own API documentation confirms that `runInShell: true` uses `cmd.exe` on Windows.

**Fix:** The executable path is already resolved, so run it directly with `runInShell: false`. Keep every option and the text as a separate argument. Do not attempt manual shell escaping. See the [Dart `Process.run` documentation](https://api.dart.dev/dart-io/Process/run.html).

### CR-07 [BLOCKER]: The exported Android system TTS service is a silence stub and its Dart bridge has no native handler

**File:** `android/app/src/main/kotlin/com/example/tcc_tts_neural/VoxSystemTtsService.kt:44-69`; `lib/core/system/android_system_tts_bridge.dart:6-46`; `android/app/src/main/kotlin/com/example/tcc_tts_neural/MainActivity.kt:1-5`  
**Issue:** `onSynthesizeText()` ignores the requested text and emits exactly 100 ms of zero PCM. Empty requests return without `done()` or `error()`, which can leave Android clients waiting. The bridge invokes `updateModelConfig` and `isServiceAvailable`, but repository call-chain inspection shows `MainActivity.kt:1-5` is an empty `FlutterActivity` with no `MethodChannel` handler, and the service never reads any bridge configuration. The manifest therefore exports a system TTS engine that cannot synthesize speech.

**Fix:** Implement Sherpa initialization inside the Android service process (or use upstream Sherpa's Android TTS engine source), load the model/tokens/espeak data before reporting language availability, stream actual PCM while honoring callback return values/cancellation, and always terminate callbacks. Add a real channel handler only if app-to-service configuration is needed; persist configuration because the service has an independent lifecycle.

### CR-08 [BLOCKER]: The claimed Web fallback is not in the runtime graph and the Web build imports native-only code

**File:** `lib/main.dart:3-8,78-84`; `lib/core/engine/composite_tts_engine.dart:4-8`; `lib/core/engine/sherpa_onnx_engine.dart:1-8`; `lib/core/engine/vits_onnx_engine.dart:1-6`; `lib/core/engine/web_speech_engine.dart:1-2`  
**Issue:** `main.dart` always constructs `CompositeTTSEngine`, which unconditionally imports engines using `dart:io`, native FFI, filesystem APIs, and the Sherpa plugin. `WebSpeechEngine` is conditionally exported but never imported or constructed anywhere in the application path. A Web target therefore cannot use the intended browser engine and may fail compilation on unavailable native libraries.

**Fix:** Put the engine factory behind conditional imports. The Web implementation must construct `WebSpeechEngine`; native implementations can construct the composite. Do not import Sherpa/`dart:io` into the Web compilation graph.

### CR-09 [BLOCKER]: Release APKs are signed with the public debug key

**File:** `android/app/build.gradle.kts:27-32`  
**Issue:** The release build explicitly uses `signingConfigs.getByName("debug")`. Debug keystores are not protected production credentials; shipping this configuration undermines update authenticity and prevents a safe production release lineage.

**Fix:** Create a private release keystore outside version control, load credentials from protected Gradle properties/environment, configure a release signing config, and fail the release build when credentials are missing. Also replace the example application ID before distribution.

### CR-10 [BLOCKER]: The required engine selector does not exist and the UI always claims Sherpa is active

**File:** `lib/main.dart:361-376`; `lib/core/engine/composite_tts_engine.dart:35-42`  
**Issue:** The context marks runtime engine selection as accepted, but the UI renders a constant “Sherpa-ONNX VITS Neural” label and has no dropdown/chip or call to `setEngineType()`. In default auto-failover, the active engine is likely the fake VITS fallback, so the displayed engine is also false. Users cannot select or diagnose the actual engine.

**Fix:** Expose both selected mode and actual active engine from the composite, render a selector backed by `TTSEngineType`, await `setEngineType`, stop current playback/speech during switching, and display initialization failures instead of a constant label.

### CR-11 [BLOCKER]: Streaming consumers can wait forever on errors or normal backpressure

**File:** `lib/core/pipeline/pipeline_orchestrator.dart:92-112`; `lib/core/memory/circular_audio_buffer.dart:42-46,63-67,85-91`  
**Issue:** `queue.markComplete()` runs only after the synthesis loop. If normalization or synthesis throws, a consumer blocked in `dequeue()` is never released. In addition, `enqueue()` is awaited before yielding; with the test's demonstrated usage (consume the returned stream but never dequeue the supplied queue), processing blocks permanently once `maxItems` is reached. The three-sentence test does not cross its five-item capacity and misses the deadlock.

**Fix:** Put `markComplete()` in `finally`, define one ownership model for delivery (returned stream or queue), and require/start a concurrent queue consumer before applying backpressure. Add tests with more than `maxItems` and with a synthesis exception.

## Warnings

### WR-01 [WARNING]: Tests explicitly accept fabricated silence as real inference

**File:** `test/core/engine/composite_tts_engine_test.dart:23-49`; `test/core/sherpa_onnx_engine_test.dart:23-39`; `test/core/engine/sherpa_onnx_cli_engine_test.dart:20-23`; `test/core/pipeline/pipeline_orchestrator_test.dart:9-15`  
**Issue:** Production-engine tests assert only initialization/non-empty sample count/duration. Arrays of zeros satisfy every assertion. The CLI test asserts only that its object is non-null, and pipeline “end-to-end” coverage injects `MockTTSEngine`. These tests are a direct reason the non-functional implementation appears complete.

**Fix:** Add a device/desktop integration test using the packaged real model and native library, assert engine identity and initialization, calculate RMS/peak/non-zero sample ratio, validate WAV playback, and fail when fallback occurs unexpectedly. Make CLI tests use a controlled fake executable that verifies exact arguments and writes a known WAV.

### WR-02 [WARNING]: Model detection misclassifies the actual 152-token Piper model as MMS

**File:** `lib/core/engine/onnx_model_detector.dart:19-37`; `assets/models/tokens.txt:1-152`  
**Issue:** The detector assumes every token file under 200 non-empty lines is an MMS character model. The bundled Piper Faber token table has 152 lines, so this function returns `mmsCharacter` and then claims espeak data is unnecessary. Although currently disconnected from engine initialization, wiring it in would reproduce CR-01.

**Fix:** Detect from trusted model metadata (`model_type`, `comment`, `has_espeak`) or a model manifest shipped with the voice. Do not infer model family from an arbitrary token-count threshold. Add a test using the actual bundled token file.

### WR-03 [WARNING]: The Windows post-build copy command does not copy to the executable directory as written

**File:** `windows/runner/CMakeLists.txt:42-53`; `windows/CMakeLists.txt:85-95`  
**Issue:** `ERROR_QUIET` is not an `add_custom_command(TARGET ...)` keyword. In the command argument sequence it becomes an extra `cmake -E copy_directory` argument, making `ERROR_QUIET` the destination and the executable directory another source (or causing a build error when the native-assets directory is absent). The top-level build already installs `PLUGIN_BUNDLED_LIBRARIES`, which is how the Sherpa Windows package exposes its DLLs.

**Fix:** Remove the redundant custom command and rely on `PLUGIN_BUNDLED_LIBRARIES`, or use exactly one source and one destination plus `VERBATIM`. Verify both `sherpa-onnx-c-api.dll` and `onnxruntime.dll` in Debug/Profile/Release output. `ERROR_QUIET` is not present in the [documented build-event syntax](https://cmake.org/cmake/help/latest/command/add_custom_command.html).

### WR-04 [WARNING]: Multi-channel WAV sizes and inserted pauses are calculated incorrectly

**File:** `lib/core/audio/wav_writer.dart:37-43,68-80`; `lib/core/pipeline/pipeline_result.dart:61-80`  
**Issue:** `AudioBuffer.durationInSeconds` treats `samples.length` as the total interleaved sample count, but `encodeToWav()` multiplies that count by `numChannels` again when sizing the data chunk while writing only `samples.length` values. Stereo output therefore contains undeclared/zero tail data and an incorrect duration. Inter-sentence pauses also add only `pauseSamples`, not `pauseFrames * numChannels`, and the combiner assumes every item has the first item's sample rate/channel layout.

**Fix:** Define samples as interleaved values, set `subChunk2Size = samples.length * bytesPerSample`, add silence per channel, and reject or resample mismatched item formats before concatenation. Add mono and stereo header/frame-count tests.

### WR-05 [WARNING]: Non-WAV input is blindly reinterpreted as Float32 at a hardcoded rate

**File:** `lib/core/audio/audio_player_service.dart:78-96`  
**Issue:** Any bytes without a RIFF prefix are viewed as native-endian Float32 and labeled 22050 Hz. PCM16 input becomes nonsense; unaligned `Uint8List` offsets can throw; arbitrary bit patterns can produce NaN/Infinity and fail WAV conversion. The API is named `loadWavBytes`, so guessing a raw format is unsafe.

**Fix:** Reject invalid WAV bytes with a clear exception. Raw audio must use an explicit API carrying sample type, endianness, sample rate, and channels; `loadAudioBuffer()` already provides the appropriate typed path.

### WR-06 [WARNING]: WAV decoding accepts malformed/unsupported files as silent audio

**File:** `lib/core/audio/wav_writer.dart:83-131`  
**Issue:** The decoder does not validate `RIFF`/`WAVE`, PCM format, declared data length, or chunk padding. It reads format fields at fixed offsets, ignores the `data` chunk's declared size, and returns a zero-filled buffer for any bit depth other than 16. CLI corruption or an unsupported WAV can therefore be reported as successful silence.

**Fix:** Parse RIFF chunks with even-byte padding, require PCM/IEEE-float formats that are actually implemented, bound reads to the declared data chunk, and throw on malformed/unsupported input. Add truncated, odd-sized-chunk, 24-bit, float, and trailing-chunk tests.

### WR-07 [WARNING]: `maxSentenceLength` is not enforced when a sentence has no soft delimiter

**File:** `lib/core/text/sentence_segmenter.dart:68-80,114-135`  
**Issue:** Once text exceeds the maximum, `_softSplitLongSentence()` returns the original text unchanged when it contains no comma, semicolon, or dash. The accumulator then keeps growing until terminal punctuation, so long EPUB prose can be sent to the model far above the requested limit.

**Fix:** Fall back to the last whitespace before the limit (and finally a hard character boundary) when no preferred delimiter exists. Add a delimiter-free paragraph substantially longer than 180 characters to tests and assert every segment respects the limit.

### WR-08 [WARNING]: The punctuation-pause implementation is dead code; playback still uses a fixed 350 ms gap

**File:** `lib/core/audio/punctuation_pause_helper.dart:77-103`; `lib/core/pipeline/pipeline_result.dart:58-74`  
**Issue:** No runtime file imports or calls `PunctuationPauseHelper`. `PipelineResult` inserts the same 350 ms silence after every sentence, so comma/question/exclamation/ellipsis rules, speed scaling, intensity, and jitter never affect generated audio despite being presented as implemented functionality.

**Fix:** Integrate pause decisions at the sentence/audio boundary using Float32 frame counts at the actual sample rate and channel count. Make pause timing deterministic for tests and align it with playback speed policy.

### WR-09 [WARNING]: Sentence highlighting ignores the 350 ms pauses inserted into the WAV

**File:** `lib/main.dart:111-125`; `lib/core/pipeline/pipeline_result.dart:66-74`  
**Issue:** Highlight timing sums only each item's synthesized duration, while the combined WAV adds 350 ms between every pair. The active sentence therefore advances early by an additional 350 ms per prior sentence, creating growing desynchronization over a chapter.

**Fix:** Build and retain a timeline while combining audio, including pauses and any resampling, then use those exact start/end offsets for highlighting and seeking.
