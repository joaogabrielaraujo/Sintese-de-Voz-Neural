# Phase 15.1 Context

## Objective

Stabilize and calibrate the existing Supertonic 3 integration without removing or replacing the Faber Piper/VITS reference engine. The phase must produce an evidence-based adaptive reading pipeline before Phase 16 academic telemetry.

## Locked decisions

- Keep Faber functional as reference and fallback.
- Keep Supertonic INT8 as the initial Android target.
- Load Supertonic once per reading session in a dedicated background isolate.
- Default to one active Supertonic inference. Parallel synthesis requires measured evidence of benefit.
- Keep the audio queue bounded and cancellable.
- Do not silently change the user's selected voice or speed. Record every fallback or effective-speed change.
- Preserve original sentence indexes when grouping short sentences.
- Never apply global phonetic substitutions without positive and negative A/B cases.
- Treat pronunciation defects as normalization, phonemization, tokenization, reproduction, or model limitations; do not hide model limitations by corrupting input text.
- Keep diagnostics optional and independent from widgets.

## Required scope

The implementation must investigate and, where applicable, cover:

- scheduler with one active synthesis task;
- persistent engine lifecycle and explicit disposal on reader exit or engine switch;
- bounded adaptive queue, minimum startup buffer, stale-task cancellation, and no unbounded prefetch;
- warm-up once after initialization;
- speed comparison at 1.0, 1.25, and 1.5 for generation and player playback separately;
- short-sentence batching with character/duration limits and sentence mapping;
- phonetic corpus for Brazilian Portuguese;
- Faber and Supertonic sample-rate correctness, PCM preservation, and no unnecessary WAV round trips;
- `num_threads` 1/2/3 and `num_steps` 5/6/8 experiments;
- per-sentence diagnostic metrics exportable to JSON/CSV;
- cache keyed by model, voice, configuration, speed, and normalized text;
- quality, economic, and accelerated reading profiles;
- UI event aggregation and investigation of synchronous work, large copies, logs, rebuilds, and blocking FFI;
- automated tests for lifecycle, serialization, queue, cancellation, warm-up, fallback, cache, batching, metrics, sample rates, and mocks;
- README and limitations documentation.

## Required metrics

Each diagnostic sentence record should include:

`engine`, `voice`, `speed_requested`, `speed_effective`, `num_steps`, `num_threads`, `text_length`, `synthesis_time_ms`, `audio_duration_ms`, `rtf`, `queue_size_before`, `queue_size_after`, `initialization_time_ms`, `sample_rate`, and `fallback_used`.

## Acceptance gate

The phase is complete only when Faber and Supertonic still work, no unjustified concurrent inference exists, the engine is not recreated between sentences, queue and speed adaptation are observable, sample rates are correct, F1/F5 are tested if available, phonetic limitations are documented, diagnostics are exportable, automated tests pass, and README reproduction instructions exist. No claim of real time may be made without measured RTF.

## Out of scope

- replacing Faber permanently;
- training or fine-tuning a new neural model;
- unrelated UI redesign;
- bundling a new large model without size/RAM evidence;
- claiming MOS from a single evaluator.

## Discussion decisions

### Late playback policy

- Declare the Supertonic late only when `RTF > 1.0` and the queue has fewer than 2 sentences.
- Reduce effective speed dynamically from the measured RTF, with a minimum floor of `0.75x`.
- Restore speed according to the selected profile: gradual with hysteresis for Quality and faster for Accelerated.
- Record effective-speed changes only in diagnostics; do not interrupt the reader with notifications.
- Startup buffer is profile-dependent: Quality 5 sentences, Economic 2, Accelerated 3.
- Maximum queue capacity adapts to RTF instead of using one fixed value.
- If Supertonic remains late at the speed floor, keep Supertonic and accept a pause. Do not automatically switch to Faber.

### Sentence batching

- Group by estimated audio duration, targeting approximately 8-10 seconds per batch.
- Map sentence highlighting using proportional estimated durations.
- Group only consecutive sentences from the same paragraph.
- Do not group batches containing questions/exclamations, long sentences or quotations, or siglas/numbers/proper names.

### Reading profiles

- Quality: Supertonic with `num_steps = 8`, higher thread allowance, and larger buffer.
- Economic: Supertonic INT8 with `num_steps = 5` and `num_threads = 1`.
- Accelerated: generate Supertonic at `speed = 1.0` and run the player at 1.5x.
- Profiles are explicitly selectable in the UI. They are not silently chosen by the device.

### Cache and diagnostics

- Cache is session-scoped only.
- Short clips use in-memory PCM; long clips use temporary local files.
- Cache capacity adapts to available RAM.
- Diagnostics are off by default and enabled only through developer configuration or command line.
- JSON is the canonical export format.
