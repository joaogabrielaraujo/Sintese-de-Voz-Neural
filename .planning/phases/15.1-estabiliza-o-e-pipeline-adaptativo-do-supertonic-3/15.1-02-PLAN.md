# Plan 15.1-02: Adaptive queue, batching, and speed policy

## Goal

Prevent phrase gaps and resource competition while keeping the player responsive.

## Tasks

1. Define bounded queue capacity and startup minimum using measured sentence duration and current RTF.
2. Implement an adaptive policy: normal playback with a healthy queue, conservative prefetch near RTF 1, and explicit late-state handling at queue starvation.
3. Cancel obsolete requests on seek, stop, chapter change, and engine switch. Do not synthesize unbounded future audio.
4. Add safe short-sentence batching with maximum characters/duration and original sentence-to-audio mapping.
5. Separate requested playback speed from synthesis speed. Measure generation at 1.0, 1.25, and 1.5 and player acceleration independently.
6. Implement explicit profiles for quality, economic, and accelerated reading. Log effective speed and fallback instead of silently changing behavior.
7. Add tests for bounded queue, starvation, cancellation, batching, sentence highlighting, and speed policy.

## Verification

- Player does not wait on the Flutter UI isolate for synthesis.
- No more than one default Supertonic inference is active.
- Queue size and late state are measurable.
- A 1.5x request cannot silently masquerade as 1.5x generation if the engine uses player acceleration.
