# Plan 15.1-01: Serialized persistent inference

## Goal

Make the Supertonic runtime persistent and guarantee at most one active inference by default.

## Tasks

1. Inspect the current worker, orchestrator, queue, and engine-switch lifecycle. Preserve user changes and existing Faber behavior.
2. Finish the dedicated Supertonic worker protocol: initialize once, process requests sequentially, surface recoverable errors, and dispose on reader exit or engine switch.
3. Add a scheduler boundary so prefetch requests cannot start concurrent Supertonic inference. Keep cancellation generation-aware and preserve the existing `PipelineOrchestrator` sequential contract.
4. Add warm-up after successful initialization, record its duration, and never repeat it per sentence.
5. Ensure worker initialization failure kills the worker and completes all pending requests with a recoverable error.
6. Add tests for one initialization, serialized requests, cancellation of stale work, engine switching, missing assets, and disposal.

## Verification

- Repeated synthesis does not reconstruct the ONNX runtime.
- Two queued requests are processed in order with no overlap.
- Faber and fallback tests remain green.
- Initialization and disposal are observable in diagnostics.
- Initialization failure leaves no orphan isolate or unresolved completer.
