# Plan 15.1-03: Phonetics, audio correctness, metrics, and cache

## Goal

Improve reproducibility and isolate pronunciation defects from pipeline defects.

## Tasks

1. Add the fixed Brazilian Portuguese phonetic corpus: ação, coração, execução, síntese, órgão, arquitetura, desacopladas, UEFS, TCC, ONNX, capítulo II, R$ 150,00, and 24/07/2026.
2. Record raw text, normalized text, submitted text, generated sample, observed issue, and error category for Faber and Supertonic.
3. Add A/B-tested pronunciation exceptions only when positive and negative cases support them. Document unresolved model limitations.
4. Verify Faber approximately 22050 Hz and Supertonic approximately 24000 Hz through actual audio metadata. Preserve PCM and avoid WAV disk round trips between sentences.
5. Consolidate optional per-sentence metrics with the required fields and JSON/CSV export.
6. Implement bounded optional cache keyed by model, voice, version/configuration, speed, steps, and normalized text. Add cleanup and corruption-safe writes.
7. Test metrics, sample rates, phonetic classifications, cache isolation, cache cleanup, and MockTTSEngine compatibility.

## Verification

- Different configuration keys never reuse stale audio.
- Sample-rate metadata is taken from generated audio, not rewritten.
- Diagnostics can be disabled without changing synthesis behavior.
- Phonetic rules are evidence-based and do not perform global text corruption.
