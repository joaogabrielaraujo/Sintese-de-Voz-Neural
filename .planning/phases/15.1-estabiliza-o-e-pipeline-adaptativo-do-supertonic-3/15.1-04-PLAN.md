# Plan 15.1-04: Calibration matrix, device gate, and documentation

## Goal

Produce reproducible evidence and an explicit go/revise decision before Phase 16.

## Tasks

1. Run the calibration matrix with INT8 using `num_threads` 1/2/3 and `num_steps` 5/6/8 at 1.0, 1.25, and 1.5 for Faber and Supertonic.
2. Test available Supertonic voices F1 and F5 with identical corpus and method. If assets are unavailable, document the limitation rather than inventing results.
3. Capture RTF, first latency, audio duration, queue state, initialization time, RAM, CPU, and temperature when available on Windows and Motorola G85.
4. Compare generation speed 1.0 plus player 1.5x, generation 1.25, generation 1.5, and Faber player fallback.
5. Investigate UI jank using aggregated events, synchronous file work, PCM copies, logs, widget rebuilds, and FFI calls.
6. Run the complete automated suite, add regression evidence, and update README with commands, configuration recommendations, limitations, and no-unmeasured-realtime claims.
7. Write a phase verification report with before/after table, phonetic findings, recommended profiles, remaining risks, and explicit acceptance status. Separate Windows results from Motorola G85 results and mark device-dependent claims as unvalidated when the device is unavailable.

## Verification

- Tests pass or failures are documented with reproducible blockers.
- Windows and Android results are separated.
- The recommended configuration is chosen from measured quality/performance tradeoffs.
- Phase 16 consumes the exported data without reimplementing instrumentation.
